# TEKSHER AI – контрольный набор вопросов

## Что проверяется

Контрольный набор хранится в `backend/src/test/resources/ai-golden-set.json`. Он покрывает:

- нормативные вопросы по Кыргызской Республике, России и ЕАЭС;
- вопросы об операционных шагах МЗКМ «Текшер»;
- запросы, в которых нельзя угадывать срок или лимит;
- ссылки на официальный источник, даты и статусы документов;
- ожидаемые факты и утверждения, которые нельзя допускать без подтверждения.

`AiAssistantGoldenSetTest` запускается в обычном `mvn verify` и проверяет структуру набора, адреса официальных источников, поисковые термины, маршрутизацию по юрисдикциям и распознавание ответа при недостатке подтверждения.

## Живое тестирование ответов

Скрипт `scripts/evaluate-ai-golden-set.mjs` отправляет все контрольные вопросы в работающий backend через `POST /api/ai/ask`. Он проверяет:

- что ссылки [N] соответствуют источникам, возвращённым API;
- что уверенный ответ не выдаётся без цитаты;
- что для документов со статусами «Черновик», «На проверке», «Срок действия истёк» и «В архиве» появляется предупреждение;
- что при конфликте дат действия выводится предупреждение;
- что для вопроса с указанной юрисдикцией есть релевантный источник либо помощник явно сообщает об отсутствии подтверждения.

Отчёт включает текст ответа, источник, юрисдикцию, статус, период действия и выдержку для проверки человеком. Сверка фактических утверждений с полным текстом нормы остаётся обязательной: технические проверки не заменяют юридическую экспертизу.

### Автоматический запуск в GitHub Actions

Backend workflow запускает живую проверку только если в репозитории есть Actions secret `GROQ_API_KEY`. Секрет не хранится в коде. Если он не задан, CI пропускает сетевые запросы к модели, но продолжает выполнять детерминированные тесты и сборку.

Чтобы включить живую проверку:

1. Откройте настройки репозитория GitHub: **Settings → Secrets and variables → Actions**.
2. Добавьте repository secret с именем `GROQ_API_KEY` и действующим ключом Groq.
3. Запустите workflow Build TEKSHER HUB. Если ключ настроен корректно, CI выполнит контрольные вопросы через тестовый backend.

Отчёт появится в артефактах workflow под названием `ai-golden-set-report`. Тест запускается на CI-базе данных с миграциями и контрольными материалами, а не на производственной базе данных.

### Запуск вручную

После запуска backend с настроенным `GROQ_API_KEY`, получите bearer-токен тестовой учётной записи и выполните:

```bash
TEKSHER_API_BASE_URL=http://localhost:8080 \
TEKSHER_API_TOKEN="<temporary-test-token>" \
node scripts/evaluate-ai-golden-set.mjs
```

Скрипт создаёт отчёт `backend/target/ai-golden-results.json` и завершает работу с кодом ошибки, если автоматические проверки не пройдены. Не используйте в отчёте или тестах токен рабочей учётной записи.
